# Plan: Simplify Grok Automation Workflow

## Problem
Current `grok_automation_v2.md` workflow uses persistent intermediate statuses (`image_warning`, `video_warning`, `extend_warning`) that leak across runs. It requires complex branching (Step 3A/3B/3C) and depends on `post_url` from previous runs. This makes runs interdependent and fragile.

## Solution
Rewrite workflow and supporting code so each run is fully independent. All moderation/failure retries happen **within the same run**. Final statuses are terminal: `completed`, `partial`, `failed`, `video_failed`.

## Files to Change

### 1. `.agents/workflows/grok_automation_v2.md`
Rewrite as a linear, single-run flow:

**Step 1: Get Next Pending Record**
- `python3 scripts/py/grok_tracker_v3.py --project 3 get_next`
- Extract: `id`, `prompt`, `video_prompt`, `extend_prompt`
- If no pending record → Exit

**Step 2: Navigate**
- Hardcoded URL: `https://grok.com/imagine`

**Step 3: Generate Images**
- Call `automateGrokGenerationV2({ promptText, skipImageGeneration: false })`
- On `status: 'image_moderated'` → Generate toned-down prompt, retry once immediately
  - If still moderated → Click "Generate More"
  - If still moderated → Mark as `failed`, exit
- On `status: 'ok'` → Proceed to Step 4

**Step 4: Generate Video**
- Call `triggerVideoGeneration(mode, videoPromptText)`
- On `status: 'video_moderated'` or `'video_failed'`:
  - If `video_prompt` exists → Tone it down, retry once immediately
  - If no `video_prompt` or retry fails → Mark as `video_failed`, exit
- On success → Proceed to Step 5

**Step 5: Wait for Video Completion**
- Call `checkVideoCompletion()`
- If returns `completed` → Proceed to Step 6 (extend) or Step 7 (no extend)
- If returns failure → Same retry logic as Step 4, then mark `video_failed` if retry fails

**Step 6: Extend Video (if extend_prompt exists)**
- Call `extendVideo(extendPromptText)`
- On `extendStatus: 'extend_moderated'` or `'extend_failed'`:
  - If `extend_prompt` exists → Tone it down, retry once immediately
  - If no `extend_prompt` or retry fails → Mark as `partial` (video exists), go to Step 7
- On `extendStatus: 'completed'` → Mark as `completed`, go to Step 7

**Step 7: Download Video**
- If status is `completed` or `partial`:
  - Take snapshot, find Download button, download to `/tmp/grok_downloads_project_3`
  - Run `python3 scripts/py/grok_video_downloader_v3.py --project 3 process_download <dir> <ID>`
  - Verify file exists at `project-3/assets/current/<ID>.mp4`

**Step 8: Update Tracker**
- `completed`: `python3 scripts/py/grok_tracker_v3.py --project 3 complete <ID> "<VIDEO_URL>" "<POST_URL>"`
- `partial`: New command `mark_partial <ID> "<VIDEO_URL>" "<POST_URL>"` → saves video/post URLs, status=`partial`
- `failed`: `python3 scripts/py/grok_tracker_v3.py --project 3 mark_failed <ID> "<POST_URL>"` (new command)
- `video_failed`: `python3 scripts/py/grok_tracker_v3.py --project 3 mark_video_failed <ID> "<POST_URL>"`

### 2. `scripts/js/grok_automation_v2.js`
Changes to the JS automation:

- **Remove** all `image_warning`, `video_warning`, `extend_warning` return statuses
- **`automateGrokGenerationV2`**: Return only these statuses: `ok`, `image_moderated`, `image_failed`, `video_moderated`, `video_failed`
- **`runImageGeneration`**: If `IMAGE_MODERATED` caught, return `image_moderated` (not throw). If timeout after Generate More, return `image_failed`.
- **`triggerVideoGeneration`**: If video generation fails/moderated, return `video_moderated` or `video_failed`.
- **`extendVideo`**: Return `extendStatus: 'completed' | 'extend_moderated' | 'extend_failed'`
- **`checkVideoCompletion`**: Return `status: 'completed' | 'video_moderated' | 'video_failed'`
- Add `generateMoreImages()` helper function that clicks "Generate More" and waits for new images
- Ensure `extendVideo` does NOT wait for main video completion internally (workflow will handle sequencing)

### 3. `scripts/py/grok_tracker_v3.py`
Changes to tracker:

- **`get_next`**: Only return records with `status == "pending"`. Remove priority logic for warning statuses.
- **Remove**: `mark_image_warning`, `mark_image_failed` (use `mark_failed` instead)
- **Add**:
  - `mark_failed(file_path, prompt_id, post_url)` → status=`failed`
  - `mark_partial(file_path, prompt_id, video_url, post_url)` → status=`partial`, saves URLs
- **`complete`**: Also clear any old `failed_at`, `video_failed_at` timestamps (already does some)
- Update `print_usage()`

## Edge Cases Handled
1. All 4 images moderated → "Generate More" clicked once, if still bad → `failed`
2. No `video_prompt` field → No retry possible, immediate `video_failed`
3. No `extend_prompt` field → Skip extend step entirely
4. Video succeeds but extend fails → `partial` status, video is downloaded
5. Image step fails → Entire run stops, marked `failed`, nothing downloaded

## Terminal Statuses
| Status | Meaning | Download? |
|--------|---------|-----------|
| `completed` | Image + Video + Extend all succeeded | Yes (extended video) |
| `partial` | Image + Video succeeded, Extend failed | Yes (main video) |
| `failed` | Image generation failed (even after retry) | No |
| `video_failed` | Video generation failed (even after retry) | No |

## Notes
- `starting_url` hardcoded to `https://grok.com/imagine`
- No `post_url` from previous runs needed
- Toned-down prompt generation happens inline (LLM call within the run)
- Each run is fully independent and deterministic
