# Phase-2: Project-3 Grok Imagine Automation — Implementation Plan

## Objective

Create a complete automation system for **project-3** that generates images and videos through `https://grok.com/imagine` with the following capabilities:

1. **Input format**: `prompt` (mandatory), `video_prompt` (optional), `extend_prompt` (optional)
2. **Route selection** based on parameters:
   - `video_prompt` present → **custom video prompt mode**
   - No `video_prompt` but config says spicy → **spicy mode**
   - Otherwise → **default make video**
3. **AI-driven best image selection** from 4 generated images
4. **Skip moderated images** (eye-off marker)
5. **Generate more** if not enough valid options
6. **Tone down and retry** if still no options
7. **Extend video** after completion if `extend_prompt` is present
8. **Download** final video to `project-3/assets/current/`

**Fields:**

- `video_prompt` (string, optional): Custom video generation prompt

- `status` (string): `pending` | `image_warning` | `video_warning` | `extend_warning` | `completed` | `image_failed` | `video_failed` | `extend_failed`

## JavaScript Automation Script (`grok_automation_v2.js`)

### Two-Phase API

**Phase A**: `automateGrokGenerationV2({ ... })` → `{ status, videoUrl, postUrl, mode, extendStatus }`

**Phase B**: `checkVideoCompletion()` → `{ status, videoUrl, error }`

### Parameters

```javascript
{
  promptText,           // Image generation prompt
  thumbnailId,          // Thumbnail ID for targeted click
  videoPromptText,      // Custom video prompt (null for default/spicy)
  videoType,            // 'spicy' or null
  extendPromptText,     // Video extension prompt (null if no extend)
  skipImageGeneration,  // Skip image phase (retry mode)
  postUrl,              // Existing post URL for retry mode
  tonedDownRetry        // Retry with toned down prompt
}
```

### Mode Determination

1. `tonedDownRetry === true` → `default_make_video`
2. `videoPromptText` present → `custom_video_prompt`
3. `videoType === 'spicy'` → `spicy`
4. Otherwise → `default_make_video`

### Image Selection Logic (AI-Driven)

```
1. Wait for 4 image cards to appear
2. For each card:
   a. Check for moderation marker (svg.lucide-eye-off)
   b. If moderated, skip
   c. If valid, collect image URL/index
3. If < 2 valid images:
   a. Click "Generate More"
   b. Wait for new images
   c. Re-evaluate
4. If still < 2 valid images:
   a. Return IMAGE_GENERATION_TIMEOUT with tone-down suggestion
5. If multiple valid images, select the best:
   a. Take screenshot of all valid images
   b. Use LLM vision to evaluate: realism, prompt match, appeal
   c. Select best image index
6. Click the selected image card to enter post detail view
```

**Fallback selection** (if AI vision unavailable): Select first non-moderated image.

### Extend Video Flow

```
1. After video generation completes successfully
2. If extendPromptText is present:
   a. Click "More options" button
   b. Wait for menu to open
   c. Click "Extend" menu item
   d. Wait for +6s/+10s options or prompt input
   e. Enter extendPromptText in input
   f. Click Submit
   g. Wait for extension generation to complete
   h. Return extendStatus: 'completed' or 'extend_warning'
3. If no extendPromptText, skip
```

### Error Handling & Retry Logic

| Error | First Occurrence | Second Occurrence |
|---|---|---|
| Image moderated | Mark `image_warning`, tone down prompt | Mark `image_failed` |
| Image timeout | Mark `image_warning`, tone down prompt | Mark `image_failed` |
| Video failed | Mark `video_warning`, tone down video_prompt | Mark `video_failed` |
| Extend failed | Mark `extend_warning`, tone down extend_prompt | Mark `extend_failed` |

### get_next Priority Order

1. `extend_warning`
2. `video_warning`
3. `image_warning`
4. `pending`

### Status Transitions

```
pending → image_warning → image_failed
pending → video_warning → video_failed
pending → extend_warning → extend_failed
pending → completed

image_warning → completed (on retry success)
image_warning → video_warning (if image retry succeeds but video fails)
video_warning → completed (on retry success)
video_warning → extend_warning (if video retry succeeds but extend fails)
extend_warning → completed (on retry success)
```

## Workflow Definition (`grok_automation_v2.md`)

### Step 1: Get Next Record

```bash
python3 scripts/py/grok_tracker_v3.py --project 3 get_next
```

Extract: `id`, `prompt`, `video_prompt`, `extend_prompt`, `status`, `post_url`

### Step 2: Read Config

```bash
python3 scripts/py/grok_tracker_v3.py --project 3 get_config
```

Extract: `starting_url`, `thumbnail_id`

### Step 3A: Full Flow (pending / image_warning)

1. Navigate to `starting_url`
2. Run automation script with all parameters
3. If returns `status: 'ok'` → Step 4
4. If returns `status: 'image_warning'`:
   - If starting status was `pending` → Step 6A-i
   - If starting status was `image_warning` → Step 6A-ii
5. If returns `status: 'video_warning'` → Step 6B-i
6. If returns `status: 'extend_warning'` → Step 6C-i

### Step 3B: Video-Only Flow (video_warning)

1. Navigate to `post_url`
2. Run automation with `skipImageGeneration: true`
3. If returns `status: 'ok'` → Step 4
4. If returns `status: 'video_warning'` → Step 6B-ii

### Step 3C: Extend-Only Flow (extend_warning)

1. Navigate to `post_url` (video must exist)
2. Run only extend video flow
3. If returns `status: 'ok'` → Step 4
4. If returns `status: 'extend_warning'` → Step 6C-ii

### Step 4: Sleep

Pause for 100 seconds to allow processing.

### Step 5: Check Completion

Run `checkVideoCompletion()` and evaluate status.

### Step 6: Update Tracker

**6A-i: First Image Failure**
1. Generate toned-down `prompt`
2. Update: `python3 scripts/py/grok_tracker_v3.py --project 3 update_field <ID> prompt "<new>"`
3. Mark: `python3 scripts/py/grok_tracker_v3.py --project 3 mark_image_warning <ID> "<POST_URL>"`

**6A-ii: Second Image Failure**
1. Mark: `python3 scripts/py/grok_tracker_v3.py --project 3 mark_image_failed <ID> "<POST_URL>"`

**6B-i: First Video Failure**
1. Generate toned-down `video_prompt` (if exists)
2. Update: `python3 scripts/py/grok_tracker_v3.py --project 3 update_field <ID> video_prompt "<new>"`
3. Mark: `python3 scripts/py/grok_tracker_v3.py --project 3 mark_video_warning <ID> "<POST_URL>"`

**6B-ii: Second Video Failure**
1. Mark: `python3 scripts/py/grok_tracker_v3.py --project 3 mark_video_failed <ID> "<POST_URL>"`

**6C-i: First Extend Failure**
1. Generate toned-down `extend_prompt`
2. Update: `python3 scripts/py/grok_tracker_v3.py --project 3 update_field <ID> extend_prompt "<new>"`
3. Mark: `python3 scripts/py/grok_tracker_v3.py --project 3 mark_extend_warning <ID> "<POST_URL>"`

**6C-ii: Second Extend Failure**
1. Mark: `python3 scripts/py/grok_tracker_v3.py --project 3 mark_extend_failed <ID> "<POST_URL>"`

**6D: Success**
1. Complete: `python3 scripts/py/grok_tracker_v3.py --project 3 complete <ID> "<VIDEO_URL>" "<POST_URL>"`
2. Go to Step 7

### Step 7: Download Final Video

1. Take snapshot to identify Download button
2. `browseros_download_file` with element ID
3. Set path to `/tmp/grok_downloads_project_3`
4. Run: `python3 scripts/py/grok_video_downloader_v3.py --project 3 process_download <download_dir> <ID>`
5. Verify file at `project-3/assets/current/<ID>.mp4`

## Tone-Down Logic

For all retry scenarios, the tone-down strategy:

1. Remove/replace provocative adjectives ("seductive" → "confident", "sultry" → "warm")
2. Simplify clothing descriptions
3. Remove explicit body part emphasis
4. Reduce suggestive poses
5. Make scene descriptions more neutral

The toned-down prompt should preserve the core scene and subject while removing potentially flagged content.

## Test Scenarios

1. **pending + no video_prompt + no extend_prompt** → default make video, no extend
2. **pending + video_prompt + no extend_prompt** → custom video prompt, no extend
3. **pending + no video_prompt + extend_prompt** → default make video + extend
4. **pending + video_prompt + extend_prompt** → custom video prompt + extend
5. **video_warning retry** → skip image, retry video with toned-down prompt
6. **extend_warning retry** → retry extend with toned-down prompt
7. **Terminal states** → image_failed, video_failed, extend_failed should be invisible to get_next
